# Shared brief: EmbGen LLM-as-a-Judge literature search

## The paper we are supporting
**EmbGen: Teaching with Reassembled Corpora** (Lenin, Rouse, Nicastro, Leontjeva; CBA; arXiv:2605.19394).
Target venue: **NeurIPS 2026 Workshop "Transitioning from Pre-Training to Post-Training" (pretrain2posttrain)** — non-archival short/long papers.

EmbGen is a **synthetic SFT data generation pipeline**. It decomposes a corpus into entity-description (ED)
pairs, embeds+clusters them (UMAP + KMeans/HDBSCAN), builds proximity graphs, and generates QA pairs via
proximity / intra-cluster / inter-cluster sampling with cluster-specialised system prompts.

- Student model: Llama-3-8B-Instruct + LoRA
- Baselines: EntiGraph, InstructLab, Knowledge-Instruct, no-augmentation
- Corpora: Pop-QA-Cities-20 (low heterogeneity), SQuAD-20 (mid), Wikitext-10 (high)
- Token budgets: 5M and 20M

## Their CURRENT evaluation (this is what we must strengthen)
1. Lexical overlap: BLEU-1/2/4, ROUGE-1/2/L, METEOR.
2. **LLM-as-a-judge, reference-based pointwise (single-answer grading with reference)**:
   - 4 dimensions: Factual Accuracy, Completeness, Relevance, Clarity
   - 3-level ordinal scale: Strong / Adequate / Weak
   - Judge = **GPT-5**, temperature 0, **10 repeated runs averaged**, categorical -> ordinal -> rounded back
   - **Binary Accuracy** = deterministic composition: `FactualAccuracy == Strong AND Completeness in {Strong, Adequate}`
   - Judge prompt includes prompt-injection guard + calibration notes (multi-part, numerics, paraphrase, verbosity)
3. Eval sets: **250 QA pairs per dataset**, LLM-generated by Claude-Sonnet-4.5 (multi-hop / cross-document by design).
   SQuAD-20 uses the native SQuAD eval set. **No canonical human-labelled gold set exists** — this is the core problem.

## Known weaknesses a NeurIPS reviewer WILL attack (we are hunting for literature that fixes these)
- **W1. No human validation of the judge.** No judge-human agreement statistics at all.
- **W2. Single judge; teacher/judge model overlap.** Teacher M_teach = GPT-5 for SQuAD-20 and Pop-QA-Cities-20,
  and the judge is ALSO GPT-5 => self-preference / familial bias risk. (WikiText-10 teacher = gpt-4o-mini.)
- **W3. Temperature=0 x 10 runs is near-degenerate** — it does not actually measure judge variance.
- **W4. No uncertainty quantification / significance testing.** N=250. The headline "88.9% relative uplift"
  is 0.068 vs 0.036 = ~17 vs ~9 items out of 250. No CIs, no paired tests.
- **W5. Verbosity confound.** EmbGen's win is driven by *Completeness*; longer answers score higher on
  completeness. Length is not controlled for.
- **W6. Synthetic reference answers.** The "ground truth" was itself LLM-generated, so judge scores are
  measuring agreement with another LLM, not with truth. Needs justification / claim-level grounding.
- **W7. No inter-dimension validity analysis** (are the 4 dimensions independent? Clarity is likely uninformative).

## What we need from the literature
Peer-reviewed, community-accepted methodology (ACL/EMNLP/NAACL/NeurIPS/ICLR/ICML/TACL/COLM/AAAI/TMLR
preferred; well-cited arXiv acceptable if flagged as such) that lets us:
(a) validate a judge against humans with the right agreement statistic, on a small annotation budget;
(b) mitigate and *measure* judge bias (self-preference, verbosity/length, position, ordinal-scale compression);
(c) attach statistically defensible error bars and significance tests to judge-derived metrics;
(d) do fine-grained / claim-level factuality scoring when no canonical labels exist;
(e) justify LLM-generated reference answers and evaluation sets.
